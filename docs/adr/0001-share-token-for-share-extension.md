# Share Extension authenticates with a per-device share token, not the Convex Auth session

The iOS Share Extension posts captures to the `/share` HTTP action with a long-lived, per-device **share token**. The signed-in app mints the token through a mutation and stores it in a shared Keychain access group. The backend stores only a hash, looks up the user from it, and revokes it on sign-out. This is the one place where something other than `requireUserId` identifies the user. We rejected sharing the Convex Auth session with the extension: its access token expires within about an hour, and its refresh token is single-use and rotates. An extension that refreshed it would race the app and could sign the user out. An extension that never refreshed it would queue almost every capture instead of saving it immediately.
